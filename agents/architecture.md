# Architecture Overview

This document is for AI coding agents that need to understand and safely modify this codebase.

## What This Project Is

A fully static product directory website. Built with Astro. No server. No database. No client-side JavaScript. Every page is pre-rendered to plain HTML at build time and served from a CDN.

## Data Flow

```
Markdown files (src/content/products/*.md)
  → Astro Content Collections (type-checked via Zod)
    → Static pages generated by getStaticPaths()
      → dist/ (static HTML, CSS, assets)
        → CDN / static host
```

## Three Layers

**1. Content Layer** (`src/content/products/`)
- Source of truth. Every product is one `.md` file.
- Frontmatter is validated against the Zod schema in `src/content/config.ts`.
- Changing a product means editing its `.md` file and rebuilding.

**2. Component Layer** (`src/layouts/`, `src/components/`)
- `Layout.astro` — HTML shell, `<head>` management, site header and footer.
- `SEOHead.astro` — All meta tags (description, OG, Twitter). Used inside Layout.
- `ProductCard.astro` — One card per product. Used in ProductGrid.
- `ProductGrid.astro` — Renders a grid of ProductCard components.
- `CategoryFilter.astro` — Row of filter links (All + one per category).
- Components receive props, do no data fetching, have no side effects.

**3. Page Layer** (`src/pages/`)
- `index.astro` — Homepage. Fetches all products, renders featured and all.
- `category/[category].astro` — One page per category. Generated via `getStaticPaths()`.
- `product/[slug].astro` — One page per product. Generated via `getStaticPaths()`.
- Pages are the only layer that calls `getCollection()`.

## Key Invariants

- `src/content/config.ts` defines the contract for all product data. Never bypass it.
- Category pages are generated from product data. There is no hardcoded category list (except the nav in Layout.astro).
- Product slugs come from filenames. URL `/product/my-product` requires file `src/content/products/my-product.md`.
- All CSS lives in `src/styles/global.css`. There is no CSS-in-JS, no Tailwind, no scoped styles.
- There is no JavaScript in the browser. Do not add `<script>` tags unless absolutely necessary.

## CSS Architecture

Single file: `src/styles/global.css`

Organized into sections (with comment headers):
1. Reset & Root (CSS custom properties / design tokens)
2. Base (html, body, a, img)
3. Layout (.container)
4. Header
5. Footer
6. Hero section
7. Page header (category pages)
8. Sections
9. Category filter
10. Product grid
11. Product card
12. Product detail page
13. Product content (Markdown body)
14. Related products
15. Responsive breakpoints

When modifying styles, locate the relevant section by the comment header.

## Build System

Astro handles everything:
- Content collection validation (Zod) at build time
- Static path generation
- HTML rendering and compression
- Asset bundling

No webpack, no Vite config needed (Astro configures Vite internally).

## File Naming Conventions

- Astro components: `PascalCase.astro`
- Page files: `lowercase.astro` or `[param].astro`
- Product markdown files: `kebab-case.md`
- CSS classes: `kebab-case`

## What NOT to Do

- Do not add React, Vue, or any client-side framework.
- Do not add a database or API routes.
- Do not hardcode the category list in multiple places — derive it from product data.
- Do not add `client:load` or any Astro client directives unless there is a clear, justified need.
- Do not modify `dist/` directly — it is generated on every build.
